# FeiCe 业务侧栏与工作区布局验收记录

## 本轮范围

本轮沿用 A2 明亮配色，调整业务侧栏的出现条件、页面操作层级和响应式布局。

| 页面 | 最终结构 |
| --- | --- |
| API 请求、API 用例 | 全宽标题与操作区；可收起的接口目录 |
| API 环境 | 全宽内容，不挂载无关目录 |
| API 执行记录、测试报告 | 全宽内容，顶部可搜索目录筛选及清除入口 |
| UI 页面、步骤、用例 | 可收起模块目录，当前模块同步到新打开的子 Tab |
| UI AI 模式、执行记录、批次、公共数据、环境、执行器 | 全宽内容，不常驻模块目录 |
| 用例、套件、缺陷 | 统一目录工作区；详情和编辑优先使用完整内容宽度 |
| 测试报告中心 | 生成操作放入页头，范围选择与报告快照放入按需面板 |
| 需求评审与专项分析 | 模块/分析维度按需打开，正文留在主内容区 |
| AI 对话 | 页头提供新对话；历史会话支持收起和移动端抽屉 |
| 个人中心 | 两个原生横向页签，支持键盘切换，320px 不隐藏密码入口 |
| APP 场景编排 | 组件库与步骤属性可独立收起，画布始终保留 |

目录在 1440px 及以上默认展开；1024–1439px 默认收起；小于 1024px 使用抽屉。用户选择按工作区保存，手机打开抽屉不会覆盖桌面偏好。资源目录首次使用时才挂载，访问后保留实例，避免切换 Tab 丢失筛选。

目录只保留低强调的新增入口和节点菜单。原有新增、编辑、删除、移动和复制入口均保留。节点菜单支持键盘；抽屉支持背景隔离、焦点约束、Escape、遮罩关闭与触发按钮焦点恢复。删除确认与业务权限仍由原组件负责。

设备元素抓取、脚本编辑、Trace 网络请求与 JSON 预览等专业编辑面板保留任务所需的分区，不作为全局业务导航常驻显示。

## 复验发现并修复的问题

1. 持久化的 `false` 被当作字符串，刷新后目录错误恢复展开。
2. 异步目录加载触发选中态同步，导致正在打开的手机抽屉自动关闭；现在只在明确选择资源后关闭。
3. 目录清除与树选中态不同步、新访问的 UI Tab 未继承模块筛选。
4. 关闭节点菜单后，触发按钮拦截 Escape，阻止继续关闭外层抽屉。
5. 个人中心在 320px 将第二个设置入口隐藏到菜单溢出区。
6. 缺陷筛选使用固定列数且叠加旧容器内边距，挤压排序选择器；改为自动换行并在工作区内清除重复内边距与固定宽度覆盖。

## 复验命令与产物

设置可用的 `PLAYWRIGHT_MODULE`、`UI_BROWSER_CHANNEL` 和 `UI_BASE_URL` 后，在前端目录运行：

```powershell
npm run build
npm run test:workspace:directories
npm run test:asset-details
npm run test:request-editor
$env:UI_SCOPE = "builder"
npm run test:workspace:forms
Remove-Item Env:UI_SCOPE
npm run test:layout:interactions
```

工作区专项支持 `UI_WIDTHS` 和 `UI_CHECKS`，可按宽度和场景名称复查。主要报告保存在被 Git 忽略的 `FlyTest_Vue/playwright-screenshots/`：

- `contextual-acceptance-a/`、`contextual-acceptance-b/`：最终构建完整六尺寸验收。
- `contextual-acceptance-bug-final/`：缺陷筛选与编辑在最终样式修复后的六尺寸复验。
- `contextual-acceptance-summary.json`：按场景和宽度合并后的 180/180 汇总。
- `contextual-acceptance-details/`：有数据的需求/报告/用例详情与编辑。
- `contextual-request-editor-complete/`：API 请求编辑。
- `contextual-builder/`：APP 步骤与编排。
- `contextual-navigation-final/`：主导航、主题、账户与认证交互。

后端、数据库、质量指标阈值和品牌资源未变更。本轮不自动提交或推送 GitHub。
